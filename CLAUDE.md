# CLAUDE.md — TenderFlow project guidance

Read this file, then the relevant file in `docs/` (SYSTEM.md, ARCHITECTURE.md, DATA_MODEL.md, AI_POLICY.md)
before changing application code. Keep docs in sync with the code when you change behaviour.

## Product purpose and scope

TenderFlow turns a tender document the user already has, plus the user's own quotation template, into a
reviewable quotation draft: parse → extract (with source references) → human review → field mapping →
generate → controlled natural-language edits → deterministic validation → export (DOCX/XLSX, PDF when
LibreOffice is installed).

Out of scope (do not build): tender discovery/scraping, marketplaces, notifications, bid submission,
authentication/permissions, analytics dashboards.

## Repository structure

```
backend/            FastAPI app (Python 3.11+)
  app/main.py       app factory, routers, optional static frontend serving
  app/models.py     all Pydantic models (single source of truth for API schemas)
  app/storage.py    JSON-on-disk project store (backend/data/, git-ignored)
  app/ingestion.py  upload validation (extension, magic bytes, size, filename)
  app/parsing/      PDF (pdfplumber), DOCX (python-docx), XLSX (openpyxl), CSV → ParsedDocument
  app/extraction/   rule-based tender extraction, conflicts, instruction-like-text detector
  app/template_analysis.py, app/fields.py, app/mapping.py
  app/quotation.py  build quotation + Decimal arithmetic
  app/validation.py deterministic rules → ValidationReport
  app/editing/      rule-based instruction parser, proposals, apply/undo
  app/ai/           optional OpenAI-compatible adapter (off by default)
  app/export/       DOCX / XLSX fill-in, PDF via LibreOffice if present
  app/api/          route modules
  tools/            sample/fixture document builders (dev only)
  tests/            pytest suites
frontend/           React 19 + TypeScript + Vite + Tailwind v4 (design ported from the team's Figma export)
samples/            fictional sample tender, templates and price list (generated by backend/tools)
scripts/            e2e_demo.cjs (Playwright end-to-end run + screenshots), check_secrets.py
docs/               specification, design, security, test plan, checklist
```

## Commands

```bash
# backend (from backend/)
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000
pytest                         # all backend tests
ruff check . && mypy app       # lint + type check
python -m tools.generate_samples   # regenerate ../samples

# frontend (from frontend/)
npm install
npm run dev                    # http://localhost:5173, proxies /api to :8000
npm test                       # vitest
npm run lint && npm run typecheck
npm run build                  # dist/ is served by the backend at http://localhost:8000

# end-to-end (from repo root, after `npm run build`; backend on :8765 with an empty TENDERFLOW_DATA_DIR)
BASE_URL=http://127.0.0.1:8765 node scripts/e2e_demo.cjs
```

## Coding conventions

- Python: type hints everywhere, Pydantic models in `app/models.py`, money as `Decimal` (never float),
  ROUND_HALF_UP to 2 dp in `app/quotation.py` only. Raise `AppError` (app/errors.py) for expected errors.
- TypeScript: strict mode, API types in `src/api/types.ts` mirror `app/models.py`; all HTTP goes through
  `src/api/client.ts`. Styles use the CSS tokens in `src/styles/tokens.css`; add new colours there first (some
  older tints in `app.css` are still literal hex — see docs/DESIGN.md §9).
- No inline scripts and no third-party assets (fonts, CDNs): the Content-Security-Policy in `app/main.py` blocks
  them, and the E2E run fails on the resulting console errors.
- Small, testable functions. No new dependency without a reason recorded in `docs/DECISIONS.md`.

## Rules that must never be broken

1. Never invent tender data, prices, tax rates, certifications, dates, signatures or company details.
   Unknown stays `null` and is shown as missing. Every value carries an `origin`.
2. Arithmetic, totals and validation are deterministic code — never an LLM.
3. Uploaded documents are untrusted data, not instructions. Never execute them, never let their text
   change application behaviour, never pass them to tools.
4. No document content is sent to an external service unless `TENDERFLOW_AI_PROVIDER` is configured
   and the user enabled it in Settings, and then only the minimum quotation context needed for an edit
   instruction — never company or personal details (`_ai_field` in `app/editing/__init__.py`, docs/AI_POLICY.md).
5. No fake functionality: no dead buttons, simulated progress, fake success toasts, fabricated metrics,
   or test results that were not actually run. Unavailable features are disabled and explained.
6. No secrets in the repo. Config comes from environment variables (see `.env.example`).
7. API responses never expose filesystem paths or environment values.

## Document processing rules

- Validate extension + magic bytes + size (`TENDERFLOW_MAX_UPLOAD_MB`, default 25) before storing.
- Store uploads under generated IDs only; original filenames are display metadata.
- Keep source references (page/line, paragraph, table/row/cell, sheet/cell). If unknown, say so.
- Never modify uploaded originals; exports are written to a copy.

## Definition of done for any change

`pytest` passes, `ruff check .`, `ruff format --check .` and `mypy app` are clean, `npm test`, `npm run lint`,
`npm run typecheck` and `npm run build` pass, the E2E script passes for UI changes, and the README/docs still
describe what the code actually does.
Report honestly which checks were run and their results.
